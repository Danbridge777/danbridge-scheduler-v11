# Danbridge 備份與還原演練

## 演練紀錄

- 日期：2026-08-08
- 環境：Firestore Emulator（獨立非正式專案 `danbridge-rules-test`）
- 正式資料：未讀取、未匯出、未修改

- 結果：通過

## 演練流程

1. 建立包含 16 個資料集合的測試快照。
2. 建立 JSON 備份、各集合筆數及 SHA-256 校驗碼。
3. 將 Emulator 中的主資料改為空集合，模擬資料遺失。
4. 解析備份並先驗證校驗碼。
5. 將備份寫回非正式 Firestore。
6. 比對所有集合筆數。
7. 驗證課程與學生、老師、校區的關聯。
8. 驗證補課與原課、收款紀錄與學生的關聯。
9. 比對完整還原資料與原始快照。

## 網站備份格式

網站匯出的 `Cloud Backup V3` 包含：

- `schemaVersion`
- 匯出時間與資料來源
- 16 個集合各自的筆數
- 針對完整集合內容計算的校驗碼

匯入時會先檢查集合筆數與校驗碼；不一致時停止匯入，不會取代目前資料。舊版無校驗碼備份仍可匯入，但確認畫面會明確標示為舊版。

## 重複驗證

執行 `npm run test:rules`。其中「非正式環境備份還原演練」必須通過，且不得改用 production 或 staging 專案 ID。

## 正式 PITR 演練邊界

- 正式資料庫已開啟 Point-in-time recovery 與 deletion protection。
- 緊急還原一律先由指定時間點建立「新的暫存資料庫」，不得直接覆蓋 `(default)`。
- 暫存資料庫必須先核對 16 個集合筆數、關聯完整性與資料 hash，再產生差異報告。
- 網站內的版本／檔案復原同樣先建立 15 分鐘有效的後端差異預覽，只有相同 plan hash 才能提交。
- Time Machine 只備份本機檔案，不是網站資料來源，也不是正式還原流程的必要條件。
- 演練或部署不得觸發正式月結、批次刪課、資料復原或帳號權限變更。
