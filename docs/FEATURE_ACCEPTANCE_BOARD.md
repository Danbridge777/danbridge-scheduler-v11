# Danbridge 功能清單與驗收狀態看板

最後盤點：2026-08-07  
基準分支：`main`  
狀態依據：目前程式碼、Firebase 設定、`tools/validate_project.py`、`tools/audit_scenarios.js` 與正式站既有操作結果。

## 狀態定義

| 狀態 | 定義 |
|---|---|
| 已自動驗收 | 有可重複執行的測試，且目前通過。 |
| 已人工驗收 | 已在正式站依明確步驟操作通過，但仍應補自動測試。 |
| 部分完成 | 功能已存在，但缺少關鍵邊界、測試、稽核或營運程序。 |
| 未開始 | 尚無可驗收的實作。 |
| 需要決策 | 需由 Owner 決定政策、範圍或外部服務後才能實作。 |

完成一項功能至少需要：驗收條件、程式或設定、正常／錯誤／權限案例、靜態檢查、本機 commit、正式部署與正式站煙霧測試。

## 執行順序

1. **P0-01：Firestore Rules Emulator 權限測試**——先證明 Owner、老師、校區管理者的允許與拒絕邊界。
2. **P0-02／P0-03：補齊課表範圍與衝堂自動回歸**——把已人工修好的核心功能固定下來。
3. **P0-06：錯誤監控最小版本**——先收集版本、錯誤類型與操作區域，不收敏感內容。
4. **P0-05：備份還原演練**——在 staging 驗證還原，而不是直接碰正式資料。
5. **P1-09：月結鎖定快照與調整單**——防止歷史財務因日後改課被重算。
6. 完成以上項目後才開始家長入口與付款串接。

## 看板更新規則

- 只有「驗收條件全部通過」才能標記為已驗收。
- 人工驗收必須記錄日期、角色、裝置、資料範圍與操作結果。
- 自動測試必須可在乾淨環境重複執行，不依賴正式資料。
- 功能狀態變更時，同一個 commit 內更新本看板與 `CHANGELOG.md`。
- 發現回歸時立即降回「部分完成」，不得保留綠色狀態。
